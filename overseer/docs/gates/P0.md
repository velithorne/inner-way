### O. Unresolved issues and notes

1. **Repository boundary (M)** - one user action required.
2. **Visibility:** `inner-way` is a public repository, so the OVERSEER P0 code and docs pushed there
   are publicly readable. The standalone repository should be created **private**.
3. **Object store fidelity:** S3Mock does not validate credentials/IAM, so credential mistakes are
   not caught locally (ADR 0001). Production uses a real S3-compatible service (P18).
4. **Defect found and fixed during this work:** the first compose file mounted a root-owned volume
   under S3Mock (non-root), so every bucket call returned HTTP 500 and `/health` failed with
   `HTTP_500`. This was invisible until the real stack was run. Fixed (ephemeral storage +
   healthcheck); documented in the ADR 0001 amendment.
5. **CI housekeeping:** the run warns that `actions/checkout@v4`, `setup-node@v4`,
   `upload-artifact@v4` and `pnpm/action-setup@v4` target Node 20 (forced onto Node 24). Not a
   failure; bump the action majors and pin by SHA during hardening (P17).
6. **Docker Hub rate limits** can affect image pulls (seen in the build sandbox, not on this CI run);
   the workflow retries pulls a bounded number of times.
7. Evidence is for commit `1d1c6ca`; later commits on the branch change documentation only.
8. The Windows local smoke test (`pnpm install`, `pnpm infra:up`, `pnpm gate:p0:health`, open the web
   shell) is still to be done by the user on their development PC.
9. The root Expo `tsconfig.json` of `inner-way` has no `include`/`exclude`, so a root `tsc` would also
   see `overseer/`; moot once OVERSEER moves out.
