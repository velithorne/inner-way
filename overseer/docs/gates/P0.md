# Gate P0 - Repository & Safety Spine

Source: build package v1.1 §12 (P0) and §18 (first session). Scope expansion is prohibited
until this gate is explicitly accepted by the user.

## Build tasks

- [x] Initialise pnpm monorepo and TypeScript strict mode.
- [x] Add lint / format / typecheck / test commands.
- [x] Docker Compose: Postgres + Redis + local S3-compatible storage.
- [x] Create `.env.example` and secret scanning rules.
- [x] Create `CLAUDE.md`, ADR template, gate template.

Per §18 the layout also includes `apps/web`, `apps/api`, `packages/{contracts,workflow,
receipts,test-fixtures}`, an API `/health` endpoint that checks its dependencies,
`.gitignore` secret-safety defaults, and ADR/gate/runbook documentation folders.

## Explicitly out of scope for P0

Shopify, Printify, supplier/3PL, AI image generation, procurement and marketing
integrations. No domain schemas (P1), no workflow transitions (P1), no agents (P2), no
facility UI (UI-01). The `workflow` and `receipts` packages are empty scaffolds.

## Evidence report (2026-10-01)

Verified from a fresh `git clone` of the branch (no `.env`, no `node_modules`):

| #   | Criterion                                | Result      | Evidence                                                                                            |
| --- | ---------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------- |
| 1   | Fresh clone installs and starts          | PASS        | `pnpm install --frozen-lockfile`; API starts from fake `.env.example` values only                   |
| 2   | lint / typecheck / test pass             | PASS        | `pnpm check` exit 0 (format, lint, typecheck in 6 projects, 49 tests, secret scan); `pnpm build` OK |
| 3   | No secret committed; `.env` ignored      | PASS        | `pnpm secrets:scan` clean; planted key was detected; `git check-ignore -v .env` hits `.gitignore:8` |
| 4   | `/health` confirms DB/Redis/object store | **PARTIAL** | See caveat below                                                                                    |
| 5   | Gate report produced                     | PASS        | this section                                                                                        |

**Criterion 4 caveat.** `/health` was exercised live against real Postgres 16 and Redis 7 started
with `docker compose`, and a real S3-protocol server (`s3rver`, a stand-in outside the repo):
200 when all up; 503 with a specific code (`ECONNREFUSED`) when Redis, Postgres or the object
store was stopped; recovery to 200. The compose `objectstore` service (Adobe S3Mock) was **not
started**: Docker Hub's anonymous pull rate limit blocked the image pull in the build
environment. Its env var names, port and HeadBucket/path-style support were checked against the
upstream README only. **Run `pnpm infra:up` and the `/health` check once locally to close this.**

Other verified behaviour: the API refuses non-local hosts when `OVERSEER_ENV=local` and prints
variable names only; logs carry `correlation_id` and redact auth/cookie headers (mutation-tested);
the web shell renders three CONNECTED tiles at 1440x900 with a clean console.

Known gaps / decisions for the user: see ADR 0001 (S3Mock instead of MinIO; TypeScript 6.0.x
pin; `overseer/` location). No CI workflow is added in P0. The repository root's Expo
`tsconfig.json` has no `include`/`exclude`, so a root-level `tsc` would also see `overseer/`.
